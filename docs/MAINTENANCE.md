# 開発・再現性・図の保守

[README](../README.md) / [図アトラス](FIGURE_INDEX.md)

## ディレクトリの役割

- **`tem_analyzer/`**：利用者向けの共通CLI。プロトタイプモデルの対応状況を明示。
- **`experiments/vN/`**：過去研究のコード・結果・図。破壊的に上書きしない。
- **`demo_data/`・`results/`**：人工教師データと初期結果。実TEMの正解と混同しない。
- **`docs/`**：計測方法、評価、図、総合結果の正本。
- **`.github/workflows/`**：`repository-quality.yml`は通常CI、それ以外の高負荷・歴史的な計算は手動ワークフロー。

## 更新手順

1. 新たな研究結果は`experiments/vNN/`に、スクリプト・使用データのハッシュ・metrics.json・輪郭画像をセットで追加。
2. 各図はMarkdownの画像埋め込み構文を使って**直接表示**。相対パスは元ファイルの実在を検証。
3. `python scripts/refactor_repository.py`で、テーマ別の全図アトラスを再構築。
4. `python scripts/check_repository.py`でMarkdown内部リンクの実在と図掲載率を検証。
5. `python -m unittest discover -s tests -v`、既存実験の小型回帰テストを実行。
6. ルートREADMEには結果の**条件付き**要約を更新。テスト画像群が違えば数値を単純比較しない。

## 画像の保管

**158点（整理時点）の既存画像は全件を保管し、図アトラスに掲載。** 同名ファイルでも版ごとに意味が異なるため、画像自体は安易に重複削除しない。人工画像やマスクも「図」カテゴリとして一覧へ埋め込む。

公開文献から得た画像は、原著へのリンク・権利表示を維持。DM3のバイナリデータは外部リポジトリから取得し、無断再配布しない。

## 品質基準

- 図を残したまま参照漏れにしない。すべての画像拡張子は1箇所以上のMarkdown`![..]`に直接掲載。
- Markdown内のローカルリンクをすべて検証。対象がない場合はCIを失敗させる。
- 行単位のCSVやビッグデータを全体像の図と混同しない。
- CIで元データをダウンロードする再現ワークフローは、通常のpushで何本も自動実行してmainを汚さないよう**手動トリガー**を原則とする。
