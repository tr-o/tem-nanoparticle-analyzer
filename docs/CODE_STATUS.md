# コードとモデルの現状 — 「最新版」は何か？

[README](../README.md) / [利用方法](USER_GUIDE.md) / [検証](VALIDATION.md) / [モデル登録簿](../models/README.md)

## 現在の結論

**これまでの研究で、精度は改善してきました。しかし、v1→v15のすべてが順次1つの完成されたモデルに統合されたわけではありません。**

研究コードと結果は `experiments/vN` に歴史的スナップショットとして残しますが、**ユーザーが実行する入口は `python -m tem_analyzer` の1系統**です。バージョン番号をアプリの別系統として増やすのではなく、実測データで再評価してから機能を共通コードに昇格させます。

## 現行モジュール

| 場所 | 責務 |
|---|---|
| `tem_analyzer/cli.py` | 一つのCLI、実験パイプラインの用途を明示して起動 |
| `tem_analyzer/legacy_rf.py` | 初期の明視野TEM向けRF：特徴量、学習、Watershed、CSVと可視化（模擬データのデモ用） |
| `tem_analyzer/geometry.py` | ROI輪郭の共通座標と描画。不一致はエラー |
| `tem_analyzer/app_brightfield.py` | 初期RFの実験GUI（Gradioオプション） |
| `scripts/run_demo.py` | 合成TEMの再生成・RFの再学習・評価用スクリプト |
| `models/` | 配布RF2種と用途明記。性能評価済みの新型という意味ではない |
| `experiments/v8/` | DM3/DM4とHRTEMの探索的な実装。CLIから明示指定して利用可能 |
| `experiments/v13/`, `experiments/v15/` | EMPS教師あり境界学習・評価の研究スナップショット |

## なぜv15を既定モデルにしないのか

v15は **EMPS（TEM/SEM混合）の未使用20視野**で、教師28枚→96枚にするとmicro-F1が23.14%→34.66%に改善した実験です。

これは既定モデル `models/synthetic_rf.joblib` または `models/weak_tem_rf.joblib` がv15のF1を得たことを意味しません。現在のv15学習済みモデルはリポジトリの`models/`には同梱していません。別装置・別撮影条件のDM3での再評価、モデル固定、単位校正などが必要です。

## モデル統合・昇格のルール

1. 同じモデルの**ソース、学習設定、学習データID、シリアライズ成果物**が揃っていること。
2. 新しい独立した撮影視野で粒子単位precision/recall/F1と粒径誤差を測ること。
3. 明るい/暗い粒子、重なり/接触、スケール校正失敗などを検査すること。
4. 既存モデルとの**同じテスト画像での比較**と画像を文書に直接埋め込むこと。
5. 合格した場合のみ`tem_analyzer/`の明示的な推論方法へ統合し、モデル登録簿を更新。失敗例は`experiments/`に保持。

## いま残る技術的負債

**v8 HRTEM探索法とv13/v15インスタンス境界学習はまだ別コード**です。現行のCLIはそれらを明示的に呼び分けていますが、統一した本番向け予測API・新DM3への汎化試験・安全なモデル自動選択は未完成です。

したがって、今回のフォルダ整理は**完成度の偽装ではなく、研究スナップショットと配布コードを分離する土台**です。今後は検出方法を単にv16、v17…と増殖させず、評価で優位性が示された機能だけを共通ライブラリへ取り込みます。
